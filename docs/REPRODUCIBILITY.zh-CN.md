## 为发布所做的改动

- 作者原有 `data_availability` 目录中的文件未改动。
- 清除了 notebook 的保存输出和执行计数，保留代码单元顺序和科学数值。
- 从已有 UVLF 绘图项目中找回缺少的输入文件。原文件校验值见 `SOURCE_MANIFEST.json`。
- 后验分析 notebook 改为读取便于分发的 NPZ 样本文件，不再要求先取得 1.9 GB 的 HDF5 链。导出时沿用原 notebook 的 `discard=30000`、`thin=1000` 和移动比例低于 0.02 时剔除 walker 的规则。接受率数据来自原始链。只有将原始 HDF5 文件放入 `mcmc/` 后，notebook 才会尝试计算完整链的自相关时间。
- MCMC 脚本改为根据脚本所在目录定位两份输入表和输出后端。
- 修复了采样启动问题：原脚本计算了初始位置，却始终向 `run_mcmc` 传入 `None`。发布副本在新建后端时传入初始位置，续跑已有链时才传入 `None`。模型函数、先验边界、初始化范围、walker 数量和采样步数均未改变。
- 本次整理没有重新计算似然、重新拟合、运行 MCMC 或重建外部限制，也没有据此声称链已收敛。

## 保留给作者核对的科学问题

1. 原后验 notebook 中标为 `16%-84%` 的章节实际调用 `np.percentile(..., [5,32,95])`。本次没有修改这些数值，不能把该单元的输出称为中位数及中心 68% 区间。
2. 若干 KDE 单元对 lambda_E 使用的硬边界为 `(-15,5)`，而采样程序和爱丁顿比三角图单元使用 `(-15,2)`。不同单元的 KDE 平滑设置也不同。作者需要选定并验证统一的报告方式，才能将这些单元共同作为一致的参数表生成流程。
3. 一个质量与丰度绘图单元使用 `[0.16,0.50,0.95]` 给 `q16,q50,q84` 赋值。变量名不能将这一组合变为 16%-84% 区间。
4. 吸积率图直接使用作者提供的摘要数值。本次没有从后验样本重新推导这些数值，也没有核对它们是否与论文 Table I 一致。
5. MCMC 输入表的表头明确标注 arXiv:2102.07775，但文件中还包含 z=9-12.5 的数据点，且没有为该数据块单独注明来源。论文将高红移输入归于 Donnan 等人（2024）；具体原表、版本及逐行对应关系仍需作者核对。
6. UVLF 理论曲线缓存记录了历史代码的哈希值。本次未证实所提供采样脚本就是生成这些缓存时使用的确切版本。重绘缓存曲线与使用当前采样脚本重新计算曲线属于不同的验证任务。
7. 所提供绘图 notebook 描述的是一种提高可读性的备选图版，采用 1 mm 标记和最低 5 pt 的 PDF 字号。成功重绘该图不能证明它满足 PRL 的全部图形格式要求。
8. 后验样本沿用原 notebook 的 walker 剔除规则。本次未验证这种剔除是否合理，也未验证 MCMC 收敛。原始链保存了 104666 步，而所提供脚本每次调用运行 60000 步；本次未还原其续跑历史。

## 完整链数据

普通 Git 跟踪不包含原始 HDF5 链。在上述限制下，可以使用处理后的 NPZ 文件运行保留的后验分析单元；该文件无法还原被剔除的 walker、所有中间步骤或完整链的自相关信息。完整链的获取方式请咨询作者；本次发布没有承诺具体的后续下载渠道。

样本文件包含以下字段：

| 字段 | 含义 |
| --- | --- |
| `chains[draw,walker,parameter]` | 处理后样本，依次为采样点、保留的 walker 和参数维度 |
| `log_prob[draw,walker]` | 对应的 emcee 对数后验 |
| `keep` | 相对于原始 walker 编号的保留掩码 |
| `bad_walkers` | 被剔除的 walker 编号 |
| `move_fraction` | 各原始 walker 在完整 burn-in 后区间的移动比例 |
| `accepted` | 各原始 walker 的接受次数 |
| `iteration` | 原始链保存的迭代步数 |
| `discard`、`thin` | 丢弃步数和抽稀间隔 |

样本权重相同。导出程序还记录原始链完整文件的 SHA-256 校验值。
